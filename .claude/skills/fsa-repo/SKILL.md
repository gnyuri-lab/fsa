# Работа с репозиторием FSA

## Что это за проект

Streamlit-приложение для автоматизированного анализа бухгалтерской отчетности РФ (формы ФСБУ 4/2023): извлечение данных из PDF/XLSX (включая OCR-сканы), верификация по контрольным формулам, расчет KPI по методологии (6 групп, Z-счет Альтмана, Таффлер), визуализация на Altair, генерация анонимизированных документов `.xlsx` / `.docx` / `.pptx`.

- Точка входа: `src/app.py` — мастер из 5 экранов (состояния в `st.session_state.current_step`: `upload` → `verify` → `amortization` → `results` → `generate`). Точный набор состояний см. в `src/app.py` (поиск по `current_step ==`).
- Опубликованный репозиторий: https://github.com/gnyuri-lab/fsa (ветка `main`, лицензия MIT).
- Полное ТЗ: `ТЗ_MVP.md` (главный документ по требованиям), приемка — `input/checklist.md`.

## Структура

Публикуемые (в репозитории):
- `src/` — код: `app.py` (UI-мастер), `data_extraction.py` (pdfplumber / Tesseract OCR / openpyxl-pandas), `analytics.py` (расчетный движок + контрольные формулы форм), `charts.py` (Altair, базовый стиль и палитра), `report_gen.py` (генерация .xlsx/.docx/.pptx + `verify_anonymity`), `extract_amortization.py` (поиск амортизации в пояснениях).
- `forms/` — пустые официальные бланки ФСБУ 4/2023 (XLSX) и их скриншоты, безопасны для публикации.
- `docs/screenshots/` — скриншоты экранов приложения для README.
- `README.md`, `ТЗ_MVP.md`, `requirements.txt`, `.gitignore`.

НЕ публикуемые (исключены в `.gitignore`):
- `input/` — реальная отчетность компании (в именах файлов есть ИНН);
- `output/` — генерируемые документы;
- `test_data/`, `reference/` (шаблон заключения с реальными данными), `information services/` (личные данные), `Шаблоны/`;
- `.claude/`, `.playwright-mcp/`, `claude.local.json`, отладочные скрипты в корне (`check_all.py`, `debug_text.py`, `find_amort.py`, `page_scan.py`, `/extract_amortization.py`), `Команда запуска FSA.txt`.

## Конфиденциальность (блокирующие правила)

1. НИКОГДА не коммитить и не публиковать содержимое `input/`, `output/`, `test_data/`, `reference/`, `information services/` — даже частично.
2. Ни в одном выходном файле (включая скриншоты и README) не должно быть названий компаний, ИНН, ФИО, должностей, телефонов (BR-03, `verify_anonymity` в `src/report_gen.py`).
3. Перед изменением `.gitignore` — не ослаблять исключения.
4. Скриншоты для README снимать только на тестовых или явно обезличенных данных; каждый скриншот перед коммитом просмотреть глазами.

## Запуск и отладка

```bash
streamlit run src/app.py          # http://localhost:8501
# фоновый/тестовый запуск:
streamlit run src/app.py --server.headless true --server.port 8501
```

- Python-окружение системное, `requirements.txt` установлен; Streamlit 1.66 уже стоит (в requirements зафиксирован 1.37 — при обновлении версии проверяй совместимость API).
- Параметр `use_container_width` устарел (лог сервера пишет предупреждения в начале каждого запуска) — это не ошибки, игнорировать при чтении логов; ошибки смотри по `Traceback` / `Exception`.
- Быстрый тест извлечения без UI: импортировать `DataExtractor` из `src/data_extraction.py` (`sys.path.insert` на `src/`), вызвать `get_structured_data(path)` на XLSX (текстовый слой точен, OCR-сканы — нет).

## Как вносить изменения

- Не переписывай работающие части без необходимости; изменения точечные, стиль — как у окружающего кода (комментарии по-русски).
- Направление расчетов зависит от согласованных правил верификации (ОФР 2200/2300 проверяются, 2400 нет; ОДДС 4310/4320 и 4400+4450+4490=4500; ОИК — по разделам; минимум 2 формы Баланс+ОФР; ошибки ОДДС/ОИК не блокируют — кнопка «Рассчитать без»; «Прочие <1%» на круговых). Проверяй, что правки не меняют эти правила без явного согласия пользователя.
- При изменении UI-потока учитывай `st.session_state`: сброс `current_step`, `extracted_data`, `excluded_forms` при новых путях.
- При изменении диаграмм: палитра и стили только в `src/charts.py` (BASE_STYLE, accent_colors); pie_top — топ-3 (салатовый/голубой/оранжевый), без легенд.
- После правок кода всегда прикладывай команду запуска и список измененных файлов + ручные проверки.

## Проверка ошибок (минимальный регламент)

1. `python -I -m compileall src` — синтаксис.
2. Прогнать быстрый тест экстрактора на синтетическом/реальном XLSX (см. выше).
3. Запустить поток «happy path» в UI: загрузить 2+ формы → «Обработать все файлы» → «Проверить данные» → подтвердить → шаги 3–5. Убедиться, что контрольные суммы прошли и пакет сформировался.
4. Скриншоты и верификацию UI можно снимать через playwright MCP (`http://localhost:8501`); перед скриншотами скрыть шапку Streamlit (`header[data-testid="stHeader"]`).
